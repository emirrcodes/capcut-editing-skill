# CapCut Editing

Use the packaged scripts relative to this SKILL.md. Silence and non-speech are separate operations. Both cutting commands default to tight pacing. Silence uses FFmpeg -30 dB / 0.08 s; non-speech uses local Silero VAD, 80 ms remaining gaps and 30 ms speech padding, with word review, whole-timeline pause review and cut verification enabled. Default captions are Turkish lowercase, usually 4–6 words, maximum 6, white with black stroke. User requests override configurable presentation and detection defaults.

## Setup and scope

Read [references/workflow.md](references/workflow.md) for commands, speech review, and subtitle-spec details. Run scripts/setup.py if needed, then use its reported virtualenv Python to run scripts/capcut_tool.py doctor. FFmpeg is a separate dependency. CPU Silero VAD is installed on all platforms; transcription uses MLX Whisper on Apple Silicon or faster-whisper on Windows/Intel.

Resolve the exact project name or supplied path; require clarification only for a missing/ambiguous project. Inspect the current disk draft before every new request. Never reuse a prior transcript after user changes. Support single-timeline, forward 1.0x linear projects. The tool rejects encrypted drafts, inconsistent mirror copies, unsupported animated clips, and cutting a timeline with other populated user tracks. Subtitle-only operations preserve user tracks. Windows adaptation is experimental until verified in Windows CapCut; report that status honestly.

No computer/screen control is needed. Before apply/restore, the target project must be saved and closed so its cached draft cannot overwrite changes. CapCut may remain open on its home screen or another project. Process presence alone cannot tell which project is open: use --project-closed only after the user has confirmed the target project is closed; never infer closure merely from unchanged fingerprints. If its state is unknown, ask about this target project, not app-wide closure. Never kill the app or discard unsaved edits. No mandatory manual review between cutting and captions.

## Execute the requested mode

- “sessiz kısımları kes”: prepare --mode silence, preview, apply. The default amplitude-only cut detects -30 dBFS silence lasting at least 80 ms; it needs no transcription. Do not add subtitles unless requested.
- “konuşmasız kısımları kes” / “konuşma olmayan kısımları kes”: prepare --mode speech, inspect speech-analysis.json, speech-pause-audit.json, speech-cut-verification.json and preview, apply. The default tight settings match references/speech-tight.config.json; no extra tight-pace request or config is needed. Scan actual speech, cross-check current words and review pauses across the whole timeline. This mode requires local transcription even without subtitles. Preserve speech, repetitions and false starts; review uncertain ranges from the current audio. Never route this request to amplitude-only cutting or silently fall back when dependencies are missing.
- “altyazı ekle”: prepare --mode subtitles against the current disk timeline, create semantic ranges, preview, apply. Do not change the media cuts.
- Combined requests: silence + subtitles uses --mode both; non-speech + subtitles uses --mode speech-subtitles. Create semantic ranges from the newly cut timeline, preview, and apply in the same request.

Use a fresh working directory outside the CapCut project and tracked package files. Preparation records file fingerprints without writing to the project. Speech cutting scans the current timeline audio; caption modes transcribe the proposed timeline. Read the mode's report and words.json when generated. Run preview and resolve validation errors, then apply the user's authorized edit without adding a separate approval step. If source files changed, prepare again. Apply commits all mirror copies with timestamped backups and attempts recovery on failure.

Cutting checks every kept intersection with existing media clips. To avoid new pieces below 100 ms, preparation keeps extra audio inside the same original clip; it reports boundary_protection_ranges_us. Existing short clips stay whole. The low-level cutter and final validation reject new/shortened micro-clips, including after writing; never silently discard a fragment or join discontinuous source ranges to bypass this guard. Check the reported extra audio when tight pacing matters. The 100 ms output-clip guard is separate from the 80 ms pause threshold; never raise the pause threshold to 100 ms to satisfy this guard.

## Semantic captions and cut alignment

Build subtitles.json using the indexed current words.json; copy its transcript_sha256. Prefer meaningful 4–6 word phrases. Short complete phrases may have fewer words. Never pad text or strand a Turkish predicate alone solely to satisfy a word count. Split longer sentences at natural phrase boundaries. Lowercase Turkish I→ı, İ→i, including brands; remove terminal punctuation by default. Correct only obvious transcription errors supported by the audio/context via replacements; never invent speech or omit spoken words. When uncertain, listen to the rendered timeline audio using available local tools.

Keep subtitle blocks touching from 0 through the timeline end. Check ownership in both directions: the left clip's text must not spill into the right clip, and the right clip's text must not appear early over the left. A gap within one media clip is filled by the left block up to the right block's natural word start. If exactly one cut lies between the left block's spoken end and the right first word's start, end the left block and start the right block at that cut, even when the right word starts after it or the gap exceeds 0.25 s. Also retain the early-word rule: a right first word starting <=0.25 s before a cut and ending after it may align to that cut when left speech has finished. A right first word crossing a cut from more than 0.25 s before it now stops for independent current-clip audio review; do not silently keep its early start or increase the threshold. Refine its actual timing or regroup genuinely continuous speech. Words entirely before a cut stay there. Actual speech continuing through a cut keeps its natural semantic grouping; never split at every cut automatically. Multiple candidate cuts require independent current-clip audio review and refined word times or grouping, never nearest-cut guessing. The planner rejects colliding starts. Compare preview transitions with fresh raw blocks; saved words may have frame rounding uncertainty but that does not authorize carryover. Saved-only validation reports words/current_words end overflow within one known frame; fresh raw-word validation remains strict. Larger overflows or unknown frame rate stop validation. Run inspect again after a native CapCut resave; it also validates existing codex_subtitles. Relative words/current_words offsets clamp negatives to 0.

The resulting codex_subtitles track contains native CapCut type: subtitle materials, recognition/base/display text, Turkish language metadata, and word timings. Reruns replace only that track and its unshared materials. Keep user-created text tracks.

## Finish and customization

Report old/new/removed duration and effective cut_settings for cutting, caption count for subtitles, and the exact backup_suffix. Successful apply saves a persistent diagnostics_archive beside the work directory before cleaning managed temporary audio/transcripts. This archive retains effective settings, source fingerprints, word times, pause decisions, candidate verification and caption review records. It is local diagnostic data, not a tracked skill resource. Transcript review originals/evidence and independent caption review audio remain available; remove those only when the user authorizes it. On failure, clean the managed work directory after diagnostics unless it is needed for an immediate retry. Mention that reopening CapCut reloads the disk changes. The result stays editable in CapCut; export is outside this skill.

For a request to preserve natural pauses, use [references/natural-pauses.config.json](references/natural-pauses.config.json): 250 ms amplitude silence, 300 ms speech gaps and 120 ms speech padding, retaining word/pause/source checks. Otherwise keep the tight defaults. For other explicit preferences, use an external JSON configuration based on [references/config.example.json](references/config.example.json). Prepare again after changing settings. See [references/workflow.md](references/workflow.md) for restore and separate silence/speech controls.

If the user explicitly identifies a current timeline interval as containing no speech, record it in speech_reviewed_gaps with the current root draft SHA-256, integer ranges_us, and basis user-confirmed. Such reviewed intervals may override a detector label on that exact draft version; never invent user confirmation from ASR/VAD results. Keep the per-piece 100 ms guard and source verification, and report the reviewed override separately. If the draft changed, ask/reinspect the interval rather than reusing old times.

When noise or clipped speech is mentioned, inspect the current audio and the candidate removed/protected ranges, especially uncertain intervals. Help revise the selected mode's settings using that evidence. Lower VAD thresholds protect more possible speech; more padding protects word edges. VAD may retain background voices or singing and does not isolate the intended speaker. If a pass clipped words, restore the pre-edit backup before recutting: another pass cannot recover removed source ranges. A no-speech result stops without deleting the entire timeline.

With speech_verify_cut enabled, preparation transcribes the proposed cut audio and compares changes with retained source intervals and VAD evidence. Inspect speech-cut-verification.json; a changed/missing token alone does not prove speech loss. The tool refuses a source-mapping mismatch, loss of VAD-supported source audio, or loss of independently protected weak-word source intervals even when ASR still recognizes the same token. Uncertain speech stays protected. Word review does not add captions. Compression ratios above 2.4 and suspicious no-speech decoding trigger bounded independent rechecks without previous-text conditioning; unresolved ranges are kept for inspection. Invalid word alignments quarantine only their bounded segment for the same recheck; unresolved audio stays protected. Use the packaged behavior rather than modifying installed scripts. Word timestamps are approximate: word review independently rechecks intervals over 1.5 s, and words of at least 0.5 s with insufficient VAD overlap, in local context before weak-word protection. A matching independently recognized word with a shorter valid interval may replace a stretched timestamp; all other trusted words in that context are preserved. Missing words or suspect decodes keep the original interval. Read speech-long-word-rechecks.json and remaining long_word_timing_ranges_us, especially leading/trailing noise. A warning alone is not a completed review when the user reports a retained pause. This flag does not prove hallucination or authorize discarding the word. A word disappearing in a second transcript alone does not prove its audio was cut; inspect retained source ranges and the audio. A tighter pace does not authorize removing spoken repetitions or false starts. Re-read the disk timeline after CapCut resaves it, because frame rounding may change durations.

With speech_pause_review enabled, inspect speech-pause-audit.json: the whole current timeline is covered by overlapping 8 s and edge contexts, with at least two independent contexts per region. Candidate pauses need agreement from sensitive VAD and separate before/after recognition anchoring crossing words wholly on one side. This can correct early or stretched word timestamps without deleting tokens. Ambiguous/suspect anchors and VAD-only regions stay protected and are reported. Never infer user confirmation from this machine evidence, and never override raw VAD-supported source protection. Report preserved uncertainties when material. Do not finish a user-reported retained-pause request with a review of only their example interval.

Do not treat a cropped suffix recognizing a complete token as proof that its weak beginning lies after the crop. Whole-timeline pause review preserves short words (<=0.5 s, with 20 ms edges) independently recovered in uncropped local word-refinement windows, even where VAD misses them. It also protects weak words up to 0.75 s corroborated inside two distinct whole-timeline contexts (20 ms edges). Corroboration needs matching normalized tokens, overlapping times and close ends; a stretched corroborating word does not restore its entire long interval. Context-edge or suspect words cannot establish this prefix guard. The same corroborated uncropped intervals may resolve a rival stretched pause-crossing timestamp; keep the earliest supported prefix and all independent guards. See the workflow reference for the bounded refinement rules. Read independent_short_word_protection_us, independent_context_word_protection_us and context_word_protection_evidence; inspect actual source coverage even if candidate ASR prints the same word. Preserve the word when evidence conflicts.

Caption preparation automatically generates caption-audio-review.json and hashed independent context/clip audio for words over 1.5 s or crossing multiple media cuts. Preview/apply refuses unresolved flagged words, preventing stretched timestamps from hiding repeats. Compare the independent raw transcripts and actual speech before revising words; preserve repetitions and false starts. If clip ownership needs independent word timing, re-transcribe bounded current clips/windows. Use the packaged review-transcript command with the current transcript hash, exact reviewed audio ranges and evidence note to stage supported changes. It retains originals/evidence and refuses changes outside those ranges. Rebuild semantic word indexes afterward. Preserve spoken repeats and corrected caption text during timing-only repair; never silently replace existing reviewed wording with new ASR guesses.

For a genuinely slow flagged word confirmed by the generated independent audio, review-transcript may retain the word using audio_review_sha256 from the current caption_audio_review receipt and reviewed audio ranges covering that word. The tool binds that resolution to the unchanged timeline audio, independent WAVs, report and staged transcript hashes. A note alone cannot clear an unchanged flag. This records the agent’s supported audio review, not automatic proof from recognition; never supply a resolution without checking the evidence. A new correction outside the audited interval needs fresh preparation/review.
