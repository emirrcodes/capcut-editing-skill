# Commands and draft contract

Resolve SCRIPT_DIR from the installed skill. Use the virtualenv Python reported by setup.py (`.venv/bin/python` on macOS, `.venv/Scripts/python.exe` on Windows). Commands below use PYTHON and TOOL as placeholders for those absolute paths, not literal commands.

```text
PYTHON TOOL doctor
PYTHON TOOL inspect "project name or absolute folder"
PYTHON TOOL prepare "project name or absolute folder" --mode both --work-dir /outside/project/work-unique
PYTHON TOOL preview /outside/project/work-unique
PYTHON TOOL apply /outside/project/work-unique [--project-closed]
PYTHON TOOL restore "project name or absolute folder" --backup .codex-edit-YYYYMMDD-HHMMSS-microseconds.bak [--project-closed]
PYTHON TOOL cleanup /outside/project/work-unique
```

| User request | --mode | Requirements beyond Python/FFmpeg |
| --- | --- | --- |
| sessiz kısımları kes | silence | None; uses -30 dBFS amplitude detection |
| konuşmasız kısımları kes / konuşma olmayan kısımları kes | speech | CPU Silero VAD and local transcription engine/model for default word/pause review |
| altyazı ekle | subtitles | Transcription engine, model, installed font |
| sessiz kısımları kes ve altyazı ekle | both | Caption requirements |
| konuşmasız kısımları kes ve altyazı ekle | speech-subtitles | VAD and caption requirements |

Default is both for compatibility; agents must pass the mode matching the actual request. Put `--config /absolute/config.json` **before** the subcommand. An explicit project folder works even when default discovery does not.

Speech mode renders the current timeline at 16 kHz mono and scans it with Silero VAD (primary probability threshold 0.5). Every candidate gap of at least 0.08 s is reviewed at threshold 0.35 with 0.40 s of surrounding context. Long gaps are reviewed in windows of at most 30 s plus context. Quiet review audio is also scanned with analysis-only gain up to 4x; source audio volume is unchanged. Additional possible speech is kept. Retained speech gets 0.03 s padding at each edge; remaining gaps shorter than 0.08 s are preserved. These thresholds are speech probabilities, not dB values. Silence settings do not control speech mode.

Read speech-analysis.json before apply: keep_ranges_us, removed_ranges_us, strong speech_ranges_us, conservatively_protected_ranges_us, and gap_reviews show decisions on the original current timeline. Listen to uncertain ranges in speech-original.wav using available local audio tools when the recording or report warrants closer inspection. VAD detects background voices/singing too; speaker isolation is outside this mode. Missing dependencies or no detected speech stop preparation without deleting project content; never substitute amplitude detection.

Configure speech_threshold / speech_review_threshold (lower protects more possible speech), speech_padding (larger protects word edges), speech_min_gap (larger retains longer natural pauses), and speech_min_duration (minimum detected speech burst) from audio evidence. Silence uses noise_db, min_silence, merge_gap, and min_keep. Restore the pre-cut backup before preparing again to recover already removed words.

`speech_word_review`, `speech_pause_review` and `speech_verify_cut` are true by default for speech cutting. No special request is required to enable them. It requires the chosen local transcription engine/model, even in speech-only mode. The original current timeline is transcribed with word timestamps, condition_on_previous_text=False, and hallucination_silence_threshold=2.0. Quality metadata is retained. Segments with compression_ratio >2.4, or no_speech_prob >0.6 together with avg_logprob <-1, are not admitted directly into trusted word protection. Suspect intervals are re-transcribed independently once, in bounded windows with context and no previous transcript prompt. If still suspect, their intervals are kept and listed as unresolved_kept_ranges_us for closer inspection. These flags suggest a decoding problem; they do not prove the audio contains no speech.

Trusted word intervals protect speech conservatively: if their VAD overlap is below max(100 ms, 35% of word duration), keep the whole word interval with 20 ms margin. Otherwise bridge VAD gaps inside the word only up to 350 ms, adding 20 ms to those edges. The union with the VAD keep plan is retained. Word timestamps are approximate and may be stretched over long non-speech regions; intervals over 1.5 s are listed as long_word_timing_ranges_us for inspection, not automatically discarded. Before weak-word protection, intervals over 1.5 s, plus words at least 0.5 s whose VAD overlap is below max(100 ms, 35%), are independently re-transcribed once with 0.40 s context (bounded to words of at most 30 s). A trusted matching token (normalized spelling similarity at least 0.85) with a shorter interval can refine the original timing; other trusted words in that context are also preserved. Absent matches, suspect decodes, or overlong intervals preserve the original word. speech-long-word-rechecks.json records the evidence and refined/unresolved status. These unresolved intervals can retain extra noise, particularly at the beginning/end. Compare actual source-time coverage and listen when uncertain; a token missing from a second recognition alone is not proof of deleted audio. Word review never creates subtitle tracks. Its temporary transcript/recheck files are cleaned after successful apply.

Both cutting commands default to tight pacing. Silence uses noise_db=-30, min_silence=0.08, merge_gap=0.12 and min_keep=0.10; its decisions remain amplitude-only. Speech uses speech_min_gap=0.08, speech_padding=0.03 and speech_min_duration=0.08 with word review, whole-timeline pause review and cut verification enabled. references/speech-tight.config.json explicitly reproduces the default speech settings; it is not required for a normal request. The 80 ms threshold applies to remaining gaps after speech protections; VAD itself uses 100 ms minimum silence, separate from the 100 ms output-clip minimum. Review the current audio/reports and revise as needed. For an explicit natural-pause request, load references/natural-pauses.config.json: 250 ms amplitude silence, 300 ms speech gaps and 120 ms speech padding; speech checks stay enabled. Never remove spoken repetitions/false starts without a separate request. Keep VAD thresholds conservative rather than assuming higher thresholds identify noise better.

With speech_verify_cut=true (requires speech_word_review), preparation renders speech-candidate.wav and transcribes it without previous-text conditioning. speech-cut-verification.json lists missing/changed recognition tokens, their original timeline times, actual media source ranges and retained portions, plus VAD-supported coverage. It validates every proposed piece against the ordered original source intersections, including repeated source slices. Source mapping errors or loss of VAD-supported audio stop preparation. Recognition differences with retained source audio remain review flags, not proof of lost speech; do not delete repetitions or false starts. Tight-profile analysis and candidate audio must be reviewed before apply.

Before splitting, every keep range is intersected with each existing media clip. Small intersections are extended inside that same clip to at least 100 ms; existing shorter clips are preserved whole, even outside the detected keep plan. Additional retained intervals are reported as boundary_protection_ranges_us. Removed ranges are rederived from this final keep plan so old candidates cannot accidentally reappear. The direct cutter refuses new/shortened sub-100-ms pieces before mutating tracks/materials. Final proposed and disk-read validation also compare against the original draft; write-time validation failure rolls back all files. The guard concerns actual output pieces, not merely the total length of each global keep range.

Never delete mini fragments automatically or merge across skipped source time. Restoring a little audio inside the original current source limits is allowed by preparation; recovering ranges beyond those limits requires the pre-cut backup. Frame-grid conversion depends on known, verified draft frame-rate fields. CapCut can resave with rounded frame times; reread its current disk state before a later operation and do not force stale microsecond timings back into it.

Audio rendering normalizes each source slice to its requested PCM sample count. A small decoder/frame-rounding difference is padded with silence or trimmed at that slice’s tail, so later clips keep their timeline positions. The allowance is 20 ms, or one declared video frame up to 50 ms; larger differences and empty slices stop preparation. Speech reports list these corrections under audio_alignment. Preparation writes only to its working directory. Cutting alone does not add captions. Speech word review and cut verification transcribe solely to check speech preservation; amplitude-only cuts and explicitly configured VAD-only passes do not require transcription; default speech cutting does. To explicitly opt out of speech review, set all three review/verification flags false together; never do this silently because a dependency is missing. Caption modes transcribe the proposed timeline after any requested cutting; words.json lists 1-based words, starts/ends in seconds, clip_cuts_us in integer microseconds, and a transcript_sha256. Have the agent compose semantic blocks in work-dir/subtitles.json:

```json
{
  "transcript_sha256": "copy the exact current words.json hash",
  "ranges": [[1, 5], [6, 10], [11, 14]],
  "replacements": {"7": "mastercard"}
}
```

Ranges are inclusive, in order, and must cover all words exactly once. The agent chooses phrase boundaries; a fixed every-six-words algorithm is not an acceptable substitute. Corrections must retain the spoken meaning. Each block must fit max_words after replacements. No fake transcript/hash/spec examples may be applied to a real project.

Preview validates captions without writing project files. It reports phrase text and adjusted start/end timestamps, with flags identifying aligned cut transitions. Review those timings against the clip cuts and semantic ownership, then apply within the user's existing edit request. A fingerprint mismatch means prepare again from the new timeline, not force-write. Preparation/preview/apply report effective cut_settings so the selected pacing is visible. Apply verifies the original project still matches, requires the target project to be closed, preserves pre-edit files, updates draft duration metadata, and writes identical full draft payloads. There is no universal CapCut schema: unrecognized structures must stop rather than be guessed.

Supported layouts: JSON draft_info.json or draft_content.json at the project root; optional single Timelines/<id> copies and full-draft template-2.tmp mirrors. If root and timeline mirrors coexist, they must already be byte-identical. All detected full copies stay byte-identical. Existing metadata duration fields tm_duration, duration, and draft_duration are updated when present. Other metadata is preserved.

Both cutting methods support one video track with embedded audio, or one audio-only track. Cutting additional music, overlays, captions made by the user, or other timed tracks is refused to avoid accidental resynchronization. Previous codex_subtitles may be removed when recutting because their text/timing would be stale. Subtitle-only mode keeps other tracks. A source/target duration difference of at most 1 microsecond is accepted as integer frame-time rounding at 1.0x; larger differences remain unsupported. Speed changes, reversed clips, primary-clip keyframes, and existing transitions during cutting are unsupported.

Backups use exclusive creation with microsecond timestamps; older backups are never overwritten. capcut-backup<suffix>.json records file paths and checksums. restore checks this manifest, backs up the current state, then restores all listed files. A failed multi-file write attempts to recover originals; interruption or filesystem failure can still require restore. JSON edits across multiple files cannot be a single filesystem transaction. A leftover .capcut-editing.lock must not be deleted while another edit is running; after confirming no process is active, use the backup manifest to diagnose an interrupted operation.

No scripts operate the desktop, close CapCut, or export a final video. The target project must be saved and closed before writes; CapCut can remain open on its home screen or another project. If CapCut is running, apply/restore require --project-closed as an explicit record of the user’s confirmation about the target project. This flag is not automatic project-state detection and must not be supplied without that confirmation. Unchanged file fingerprints alone do not prove a project is closed. Preparation or transcription failure leaves the original timeline untouched; apply errors include recovery status. Cleanup deletes only tool-owned working filenames, never arbitrary project/media files.

User-reviewed non-speech intervals: speech_reviewed_gaps is null by default. Only after the user explicitly identifies an interval as non-speech, supply an object with draft_sha256 (the SHA-256 of the current root draft bytes), ranges_us (ordered, disjoint integer-microsecond pairs), and basis: user-confirmed. Preparation rejects stale hashes, out-of-timeline ranges, or other modes. These intervals override VAD/word protection only for this draft; the minimum-output-piece guard still applies. Verification separately reports user_reviewed_vad_override_us and unexpected_vad_supported_source_loss_us; unreviewed speech loss still stops. A recognition difference or unchanged file alone cannot establish human confirmation.

### Whole-timeline pause review

Default speech cutting enables `speech_pause_review` together with word review and candidate verification. It scans the entire current timeline in overlapping local contexts, then transcribes both sides of each candidate pause independently to locate complete boundary words. Read `speech-pause-audit.json` for full coverage, every remove/keep decision, and uncertain or VAD-only intervals. A long word timestamp must not keep a verified pause merely because it reaches into that pause. Missing recognition alone cannot authorize a cut; ambiguous syllable/repetition boundaries stay intact. All raw VAD-supported source ranges remain protected and the existing 100 ms output-clip guard still applies. This requires local transcription work and may take longer than an explicitly configured VAD-only pass.

### Caption ownership at cuts

Gapless coverage and correct clip ownership are independent checks. Use both sides of each semantic block boundary: if one cut lies after the left spoken end and before the right word starts, both captions meet exactly at that cut, including a late right word. Inside one clip, the left block fills the gap to the natural right start. A right word crossing a cut within 250 ms retains the early-alignment rule when left speech has finished. Continuous speech is not split automatically. Multiple candidate cuts stop for current clip audio review; refine actual word times/grouping rather than applying a proximity heuristic. Preview/insertion and post-write validation use fresh raw blocks. Saved-only validation reconstructs absolute times from relative word payloads with at most one known frame of uncertainty (capped at 50 ms), reports any uncertainty, and refuses larger ownership errors. A frame tolerance is not permission to shift speech. Timing-only repair should preserve corrected text/style/user tracks and use fresh audio; new ASR wording is not authority to overwrite corrected captions.

For ambiguous current word timing or missing speech in captions, independently re-transcribe the relevant current clip/window. Stage supported corrections with `PYTHON TOOL review-transcript WORK --review REVIEW.json`. The review object has `transcript_sha256` (current words.json hash), ordered integer `audio_ranges_us`, the revised normalized `transcript`, and a nonempty evidence `note`. Words outside those reviewed ranges must remain unchanged. This command checks project/preparation fingerprints, archives original raw words/evidence, and updates the working transcript/word indexes/hash; it never writes CapCut. Review archives remain on disk, including after normal cleanup; remove only when the user authorizes it. Build new semantic ranges using the new words.json. Do not change hashes by hand or reuse old ranges after word insertions. A cropped suffix recognizing a token alone cannot prove its beginning belongs to that clip; compare current clips on both sides when needed.

Before writes, commit checks SHA-256/size fingerprints twice and requires mtime_ns/size to stay stable across the interval and backup phase. A same-content rewrite during this check also stops the edit. This does not prove target-project closure; explicit closure confirmation is still required while CapCut is running.
